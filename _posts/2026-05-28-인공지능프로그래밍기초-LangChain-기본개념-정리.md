# 랭체인(LangChain)과 RAG(검색 증강 생성) 핵심 요약 및 정리

**💡 한 줄 요약:** 대규모 언어 모델(LLM)을 외부 데이터 및 도구와 쉽게 연결하여, 환각(Hallucination) 없이 정확하고 실용적인 AI 애플리케이션을 빠르게 구축할 수 있도록 돕는 오픈소스 프레임워크입니다.

---

## 1. 랭체인에서 Retrieval(검색)의 역할과 중요성

> **"랭체인의 Retrieval은 RAG의 대부분의 구성 요소를 아우르며, 구성 요소 하나하나가 RAG의 품질을 좌우합니다."**

랭체인 시스템에서 Retrieval 파이프라인은 데이터가 수집되고, 변환되며, 사용자의 질문에 맞춰 검색되어 최종 LLM으로 전달되는 RAG의 핵심 엔진입니다.

---

## 2. 랭체인 Retrieval 작동 원리 (쉽게 보는 데이터 흐름도)


### 📦 Step 1. 데이터 준비 과정 (문서를 학습/저장하는 단계)
> **[한눈에 보기]** 문서 로드 ➔ 텍스트 분할 ➔ 임베딩(수치화) ➔ 벡터 저장소에 저장

1. **문서 (Document Loaders)**: PDF, Word 등 다양한 원본 문서를 시스템으로 불러옵니다.
2. **텍스트 분할 (Text Splitter)**: LLM이 처리할 수 있도록 대용량 문서를 일정한 크기(청크)로 자릅니다. *(문맥이 끊기지 않게 겹쳐서 자르는 '청크 오버랩' 기술 사용)*
3. **임베딩 모델 (Vector Embeddings)**: 잘린 텍스트 조각들을 컴퓨터가 이해할 수 있는 고차원 숫자 데이터(벡터)로 변환합니다.
4. **벡터 저장소 (Vector Store)**: 수치화된 텍스트 데이터를 언제든 빠르게 검색할 수 있도록 전용 데이터베이스에 저장합니다.

### 💬 Step 2. 사용자 질의 과정 (질문에 답변하는 단계)
> **[한눈에 보기]** 사용자 질문 ➔ 질문 임베딩 ➔ 유사 문서 검색 ➔ 체인(결합) ➔ LLM 답변 생성

1. **사용자의 질문**: 사용자가 궁금한 내용을 챗봇 등에 입력합니다.
2. **질문 임베딩 (Embedding Model)**: 사용자의 질문 역시 검색을 위해 숫자(벡터)로 변환합니다.
3. **유사 문서 검색 (Retrievers & Vector Store)**: 숫자로 변환된 질문과 의미가 가장 유사한 문서 조각을 벡터 저장소에서 찾아 추출합니다. *(이 단계가 RAG의 정확도를 크게 좌우합니다)*
4. **체인 (Chain)**: 검색기가 찾아낸 관련 내용(Context)과 사용자의 원본 질문을 하나로 매끄럽게 엮어 최종 질문(프롬프트)을 만듭니다.
5. **최종 답변 생성 (LLM)**: 체인을 통해 전달된 검증된 정보를 바탕으로 대형 언어 모델(LLM)이 환각 없는 정확한 답변을 생성합니다.

---

## 3. RAG 도입의 필요성: 파인 튜닝(Fine-Tuning)과의 비교

전통적인 LLM은 학습 컷오프(Cut-off) 이후의 정보나 기업 비공개 데이터를 알지 못해 **할루시네이션(환각)**을 일으킵니다. 이를 해결하기 위해 파인 튜닝과 RAG를 고려할 수 있습니다.

| 비교 항목 | 파인 튜닝 (Fine-Tuning) | RAG (검색 증강 생성) |
| :--- | :--- | :--- |
| **개념** | 모델 자체의 **가중치(Weights)**를 새로운 데이터로 재학습 | 모델(LLM)은 고정하고, **벡터 저장소**의 외부 데이터만 참조 |
| **데이터 반영성** | 매번 재학습이 필요하여 실시간 반영이 매우 어려움 | 벡터 저장소 업데이트만으로 **실시간 반영 가능** |
| **시간 및 비용** | 컴퓨팅 자원 소비가 크고 구축 시간/비용 높음 | 기존 모델 성능을 그대로 활용하므로 매우 저렴하고 빠름 |

---

## 4. 랭체인(LangChain)의 추상화(Abstraction)와 문제 해결

랭체인은 복잡한 하부 로직을 사용자에게 숨기는 **추상화**를 제공하여, 개발자가 비즈니스 로직에만 집중할 수 있게 합니다.

1. **정보 접근의 제한 해결:** 외부 툴(Tools)을 활용하는 **Agents(에이전트)**나 Vector Store 검색을 통해 최신/사내 데이터에 접근합니다.
2. **토큰 입력 제한 해결:** 다양한 **Text Splitter**를 제공하여 문서를 최적의 크기로 자동 분할합니다.
3. **할루시네이션 해결:** 검색된 신뢰도 높은 Context 안에서만 답변하도록 체인(Chain) 단에서 프롬프트를 제어합니다.

## 5. 랭체인의 기타 핵심 구성 요소 (Retrieval 외)
랭체인은 RAG 시스템의 검색 기능 외에도 유연한 애플리케이션 구축을 위해 다음과 같은 핵심 모듈을 제공합니다.

* **Prompts (프롬프트 템플릿):** 모델에 대한 입력을 체계화합니다. 예를 들어 `{국가}의 {상징}은?`과 같이 텍스트 내에 변수를 할당하여, 매번 타이핑할 필요 없이 상황에 맞는 구체적인 프롬프트를 쉽게 찍어낼 수 있습니다.
* **Memory (메모리):** 기존 LLM의 '기억 상실' 문제를 해결하기 위해, 이전 대화 내용(맥락)을 저장하고 불러와 대화가 끊기지 않고 자연스럽게 이어지는 챗봇을 구현합니다.
* **다양한 Chain 연결 방식:**
  * `Sequential Chain`: 여러 작업을 사슬처럼 순차적으로(A 실행 후 결과값을 받아 B 실행) 연결합니다.
  * `Router Chain`: 사용자의 질문 성격에 따라 가장 적절한 프롬프트나 하위 체인으로 경로를 자동 선택해 줍니다.
* **임베딩의 구체적 형태:** 임베딩 모델은 문서를 `[0.132, 0.543, 0.251, ...]` 형태의 연속된 실수(Vector)로 변환하며, 보통 수백(예: 512차원)에서 수천 차원을 사용하여 단어 간의 미세한 의미적 유사도를 정교하게 수치화합니다.
