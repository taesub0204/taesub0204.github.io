## 1. 정규화 (Normalization) 와 이상 현상 (Anomaly)

### 📌 이상 현상 (Anomaly) 이란?
정규화를 거치지 않은 하나의 큰 테이블에서 데이터를 조작할 때 발생하는 불필요한 데이터 중복 및 부작용 현상입니다.

| 이상 현상 종류 | 설명 | 예시 |
| :--- | :--- | :--- |
| **삽입 이상 (Insertion)** | 원하지 않는 불필요한 데이터를 함께 입력하지 않으면 원하는 데이터를 삽입할 수 없는 현상 | 신규 과목만 등록하려는데, 수강 학생 정보가 없어 학번을 NULL로 넣거나 등록 불가 |
| **삭제 이상 (Deletion)** | 특정 데이터를 삭제할 때 의도하지 않은 다른 유용한 정보까지 함께 연쇄 삭제되는 현상 | 한 학생이 수강을 취소했는데, 그 과목 정보 전체가 시스템에서 삭제됨 |
| **갱신 이상 (Update)** | 중복 튜플 중 일부 속성만 수정하여 데이터 불일치(Inconsistency)가 발생하는 현상 | 특정 학생의 주소가 바뀌었는데 1건만 수정되어 동일 학생의 주소가 행마다 달라짐 |

## 2. 함수적 종속성 (Functional Dependency, FD)

- 어떤 속성 $X$의 값을 알면 속성 $Y$의 값이 오직 하나로 결정될 때, **「$Y$는 $X$에 함수적으로 종속된다」**고 합니다.
- 표기법: **$X \rightarrow Y$** ($X$: 결정자 Determinant, $Y$: 종속자 Dependent)

```mermaid
flowchart TD
    subgraph 완전함수종속["완전 함수 종속 (Full FD)"]
        F1["(학번, 과목코드)"] -->|복합 기본키 전체에 종속| F2["성적"]
    end
    subgraph 부분함수종속["부분 함수 종속 (Partial FD) - 2NF 대상"]
        P1["(학번, 과목코드)"]
        P1 -.->|기본키의 일부(학번)에만 종속| P2["학부전공"]
    end
    subgraph 이행적함수종속["이행적 함수 종속 (Transitive FD) - 3NF 대상"]
        T1["학번(PK)"] --> T2["학과코드"]
        T2 --> T3["학과명"]
    end
```

## 3. 정규화 단계 요약표 (별 5개 ⭐⭐⭐⭐⭐)

| 정규형 | 대상 및 핵심 분해 내용 | 암기 비법 키워드 |
| :--- | :--- | :--- |
| **1NF (제1정규형)** | 속성의 원자성 확보 (다중값, 반복 그룹 제거) | **원자값** |
| **2NF (제2정규형)** | **부분 함수 종속성 제거** (복합 기본키 전체에 종속되도록 분리) | **부분 함수 종속 제거** |
| **3NF (제3정규형)** | **이행적 함수 종속성 제거** ($A \rightarrow B, B \rightarrow C$ 일 때 $B \rightarrow C$ 분리) | **이행 함수 종속 제거** |
| **BCNF (보이스-코드)** | **결정자가 후보키가 아닌 함수 종속 제거** (모든 결정자가 후보키여야 함) | **결정자 후보키화** |
| **4NF (제4정규형)** | 다치 종속성 (Multi-Valued Dependency) 제거 | **다치 종속 제거** |
| **5NF (제5정규형)** | 조인 종속성 (Join Dependency) 제거 | **조인 종속 제거** |

> 💡 **정규화 순서 암기 공식**: **원 - 부 - 이 - 결 - 다 - 조**  
> (원자값 $\rightarrow$ 부분함수종속 $\rightarrow$ 이행함수종속 $\rightarrow$ 결정자 $\rightarrow$ 다치종속 $\rightarrow$ 조인종속)

## 4. 정규화와 성능 트레이드오프 (Trade-off)

- **성능 향상 영역**:
  - 데이터 중복이 최소화되어 저장 공간 절약
  - 데이터의 무결성이 강화되어 **입력(INSERT), 수정(UPDATE), 삭제(DELETE) 성능 대폭 향상**
- **성능 저하 영역**:
  - 테이블이 여러 개로 분할되므로 데이터 조회(SELECT) 시 **테이블 조인(JOIN) 횟수가 증가**하여 조회 성능 저하 가능
  - *대응책*: 적절한 인덱스 설계 및 필요 시 반정규화 적용

## 5. 반정규화 (De-normalization) 완벽 정리

### 📌 반정규화란?
정규화된 엔터티, 속성, 관계를 시스템의 성능 향상 및 개발·운영의 단순화를 위해 **의도적으로 데이터 중복을 허용하거나 테이블을 통합/분할하는 기법**입니다.

> ⚠️ **반정규화 적용 절차 (순서 주의!)**  
> 1. 정규화 정확히 수행 $\rightarrow$ 2. 용량 및 트랜잭션 유형 파악 $\rightarrow$ 3. 다른 방법(인덱스 조정, 뷰, 클러스터링 등) 우선 검토 $\rightarrow$ 4. 최후의 수단으로 반정규화 적용!

### 🛠️ 반정규화 3대 기법
1. **테이블 반정규화**:
   - **테이블 병합**: 1:1 관계 병합, 1:N 관계 병합, 슈퍼/서브타입 병합
   - **테이블 분할**: 수직 분할(자주 쓰는 컬럼 분리), 수평 분할(파티셔닝, 행 단위 분리)
   - **테이블 추가**: 중복 테이블 추가, 통계 테이블 추가, 이력 테이블 추가
2. **컬럼 반정규화**:
   - **중복 컬럼 추가**: 조인을 줄이기 위해 자주 조회되는 컬럼을 자식에 중복 보관
   - **파생 컬럼 추가**: 계산 부하를 줄이기 위해 합계, 평균 등의 계산값을 미리 저장
   - **이력테이블 컬럼 추가**: 최신값 조회 성능 향상을 위해 최근 변경일자, 최근 상태 등 추가
3. **관계 반정규화**:
   - 데이터 무결성을 해치지 않으면서 조인 경로를 단축하기 위해 추가적인 외래키 관계 추가

## 6. 트랜잭션과 ACID 특성

트랜잭션(Transaction)은 데이터베이스에서 하나의 논리적 작업 단위를 의미합니다.

| 특성 | 설명 | 위반 시 문제점 |
| :--- | :--- | :--- |
| **원자성 (Atomicity)** | "All or Nothing" - 전부 성공(Commit)하든가 전부 취소(Rollback)되어야 함 | 계좌이체 중 돈은 빠져나갔는데 상대 계좌에 입금되지 않음 |
| **일관성 (Consistency)** | 트랜잭션 수행 전후에 데이터베이스의 일관된 제약조건(무결성)이 유지되어야 함 | 잔고가 마이너스가 되거나 외래키 규칙이 깨짐 |
| **격리성 (Isolation)** | 실행 중인 트랜잭션은 다른 트랜잭션의 연산 작업에 끼어들지 못하게 격리되어야 함 | 다른 트랜잭션이 작업 중인 데이터를 읽어 오작동 발생 |
| **영속성 (Durability)** | 성공적으로 완료된 트랜잭션의 결과는 시스템 장애가 발생해도 영구적으로 보존되어야 함 | DB가 비정상 종료되어 커밋된 내역이 사라짐 |

## 7. NULL 속성의 핵심 이해 (2024 개정 강조 ⭐)

### 📌 NULL의 본질
- NULL은 **공백(' ')도 아니고, 숫자 0도 아니며, '정의되지 않은 값' 또는 '알 수 없는 값(Unknown)'**입니다.

### 📐 NULL 연산 규칙
1. **NULL과의 모든 사칙연산 결과는 NULL**: `100 + NULL = NULL`
2. **비교 연산**: `=` 대신 반드시 **`IS NULL`** 또는 **`IS NOT NULL`** 사용
3. **3-Valued Logic**: 조건식의 결과는 `TRUE`, `FALSE`, 그리고 `UNKNOWN` 3가지 존재
4. **집계 함수에서의 NULL**:
   - `SUM(SAL)`: NULL은 연산 대상에서 **제외(무시)**하고 계산
   - `COUNT(*)`: NULL 값을 포함한 **전체 행 수** 반환
   - `COUNT(SAL)`: SAL 컬럼이 NULL인 행을 **제외한 행 수** 반환

## 8. 본질식별자 vs 인조식별자 (2024 개정 강조 ⭐)

| 구분 | 본질식별자 (Natural Key) | 인조식별자 (Surrogate Key) |
| :--- | :--- | :--- |
| **정의** | 업무적으로 원래 존재하는 속성으로 구성된 자연스러운 식별자 | 업무적으로 의미는 없으나 관리 편의를 위해 인위적으로 부여한 일련번호 식별자 |
| **예시** | 주민등록번호, 사원번호, 계좌번호, (고객ID + 주문일자 + 순번) | 주문_SEQ, 결제_ID (Oracle SEQUENCE, Auto Increment) |
| **장점** | - 추가적인 저장 공간 불필요<br>- 엔터티 자체의 의미 명확 | - 복합키를 단일키로 단순화하여 **조인 편의성 및 SQL 작성 용이**<br>- 기본키 변경 위험 최소화 |
| **단점** | 복합키로 구성될 경우 상속 시 **하위 테이블의 PK 컬럼 수가 비대해짐** | - 중복 데이터가 삽입될 위험 존재 (**별도 Unique 제약조건 필수**)<br>- 인덱스 저장 공간 추가 소모 |
