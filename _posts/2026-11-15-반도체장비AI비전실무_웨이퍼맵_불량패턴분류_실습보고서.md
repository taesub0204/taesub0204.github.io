# Part 1. 웨이퍼맵 데이터와 CNN 분류 실험 (04강)

## 1.1. 웨이퍼맵 데이터의 특징과 분류 대상 불량 유형
반도체 제조 공정에서는 원판 형태의 실리콘 웨이퍼(Wafer) 위에 수많은 개별 칩인 다이(Die)를 제작합니다. 웨이퍼맵(Wafer Map)은 각 다이의 전기적 검사 결과와 위치 정보를 2차원 격자 배열로 기록한 데이터이며, 각 칸은 다음 세 가지 값으로 표현됩니다.
* **0**: 웨이퍼 바깥쪽의 빈 공간 (유효하지 않은 영역)
* **1**: 검사를 통과한 정상 다이 (정상 칩)
* **2**: 불량으로 판정된 다이 (불량 칩)

4강 실습에서는 웨이퍼맵 배열을 `64x64` 크기의 이미지로 변환한 뒤, 대표적인 5가지 불량 유형을 CNN(합성곱 신경망)으로 분류하는 실험을 진행했습니다.
1. `Center`: 웨이퍼 중심 부근에 불량 칩이 둥글게 모여 있는 패턴
2. `Edge-Loc`: 웨이퍼 가장자리의 일부 구역에 불량이 집중된 패턴
3. `Edge-Ring`: 웨이퍼 가장자리 둘레를 따라 고리 형태로 불량이 분포하는 패턴
4. `Loc`: 웨이퍼 내부의 특정 영역에 국부적으로 불량이 모여 있는 패턴
5. `Scratch`: 웨이퍼 표면에 선 형태로 길게 이어진 불량 패턴

전체 이미지 데이터는 총 2,351장으로, 학습 데이터(`train_ds`) 1,881장(80%), 검증 데이터(`val_ds`) 470장(20%), 그리고 별도로 분리된 테스트 데이터(`test_ds`) 150장(5개 클래스별 30장씩 동일하게 구성)을 사용했습니다.

## 1.2. [실습 코드] 데이터셋 불러오기 및 CNN 모델 구성·학습

> **[4강 실습 폴더 구조 확인 (`AIVision_04강_실습코드_v261111_보고서작성용.ipynb` 기준)]**
> `tf.keras.utils.image_dataset_from_directory()`가 5개 불량 클래스를 폴더 이름으로 자동 인식할 수 있도록, 구글 드라이브 내 `root_path` 아래에 반드시 `Train/`과 `Test/` 및 5개 클래스 하위 폴더가 아래와 같이 구성되어 있어야 합니다.


```python
# [4강 셀 1] 필수 라이브러리 임포트 및 딥러닝/머신러닝 하이퍼파라미터 기본 설정

# [실험 재현성 및 일관성을 위한 전역 하이퍼파라미터 정의]
IMG_SIZE = 64       # 모든 웨이퍼맵 이미지를 64x64 크기로 리사이징 (공간 패턴 보존과 연산량 최적화)

RANDOM_STATE = 42   # 난수 시드 고정 (데이터 분할, 초기 가중치 등의 실험 재현성 보장)
```

```python
# [4강 셀 2] Google Drive 마운트 및 tf.data.Dataset 파이프라인 생성 (Train, Val, Test)
from google.colab import drive
```

```python
# [4강 셀 3] 기본 CNN 모델 구조 정의 및 컴파일 (wm_cnn_model_261019.keras 기준)
model = keras.Sequential([
    # [입력층] 64x64 해상도, 3채널(RGB) 텐서 입력
    layers.Input(shape=(IMG_SIZE, IMG_SIZE, 3)),
    
    # [정규화층] 픽셀 밝기값 [0, 255] -> [0.0, 1.0] 부동소수점 범위로 스케일링 (경사하강 안정화)
    layers.Rescaling(1./255),
    
    # [블록 1: 저수준 공간 특징 추출] 3x3 합성곱 필터 32개, ReLU 활성화 -> 출력 형태: (62, 62, 32)
    layers.Conv2D(32, kernel_size=3, padding="valid", activation="relu"),
    # 2x2 최대 풀링으로 공간 해상도 절반 축소 -> 출력 형태: (31, 31, 32)
    layers.MaxPooling2D(pool_size=2),
    
    # [블록 2: 고수준 복합 패턴 추출] 3x3 합성곱 필터 64개, ReLU 활성화 -> 출력 형태: (29, 29, 64)
    layers.Conv2D(64, kernel_size=3, padding="valid", activation="relu"),
    # 2x2 최대 풀링으로 추가 축소 -> 출력 형태: (14, 14, 64)
    layers.MaxPooling2D(pool_size=2),
    
    # [평탄화층] 3차원 특성 맵(14, 14, 64)을 1차원 벡터(길이 12,544)로 직렬화
    layers.Flatten(),
    
    # [완전연결 은닉층] 64개 뉴런으로 고차원 특징 조합 학습
    layers.Dense(64, activation="relu"),
    
    # [출력층] 5개 불량 클래스에 대한 소프트맥스 확률 분포 출력 (합계 = 1.0)
    layers.Dense(len(class_names), activation="softmax")
])

# [모델 컴파일]
# - optimizer='adam': 학습률을 적응적으로 조절하는 모멘텀 기반 최적화 알고리즘
# - loss='sparse_categorical_crossentropy': 라벨이 원-핫 인코딩이 아닌 정수(0~4) 형태일 때 사용
# - metrics=['accuracy']: 훈련/검증 과정에서 모니터링할 정확도 지표
model.compile(
    optimizer="adam",
    loss="sparse_categorical_crossentropy",
    metrics=["accuracy"]
)

# 모델 계층 구조 및 파라미터 수 확인
model.summary()
```

## 1.4. [실습 코드] 테스트 데이터 평가, 혼동행렬 및 오분류 회전 실험

```python
# [4강 셀 5] 독립 테스트 데이터(150장) 예측 수행, 클래스별 분류 리포트 및 혼동행렬 시각화
# test_ds의 모든 미니배치로부터 실제 정답 라벨(y_true)을 추출하여 1차원 넘파이 배열로 병합

# 테스트 데이터에 대한 모델의 소프트맥스 예측 확률값 산출 (형태: 150 x 5)
y_prob = model.predict(test_ds)

# 각 샘플별로 가장 확률이 높은 클래스의 인덱스를 선택하여 최종 예측값(y_pred) 결정
y_pred = np.argmax(y_prob, axis=1)

# 테스트 데이터셋에 대한 손실값 및 전체 정확도 측정
test_loss, test_acc = model.evaluate(test_ds, verbose=0)

# [혼동행렬(Confusion Matrix) 계산 및 시각화]
cm = confusion_matrix(y_true, y_pred)
fig, ax = plt.subplots(figsize=(6, 5))
disp = ConfusionMatrixDisplay(confusion_matrix=cm, display_labels=class_names)
disp.plot(ax=ax, cmap='viridis', values_format='d') # 정수 빈도수('d')로 표시
plt.xticks(rotation=45)
plt.title('4강 기본 CNN 혼동행렬 (Confusion Matrix)', fontsize=12)
```

```python
# [4강 셀 6] 오분류된 Loc 샘플을 0°·90°·180°·270° 회전시키며 CNN의 예측 결과 변화 추적
# 테스트셋에서 실제 라벨은 Loc(국소 불량)인데 다른 클래스(예: Scratch)로 오분류된 샘플 인덱스 탐색
loc_idx = class_names.index('Loc')
mis_indices = np.where((y_true == loc_idx) & (y_pred != loc_idx))[0]

# test_ds로부터 모든 이미지 배열을 모아 오분류 샘플 1장을 선택
all_test_images = np.concatenate([x.numpy() for x, _ in test_ds], axis=0)
sample_img = all_test_images[mis_indices[0]]

print(f"오분류 탐색 완료: 테스트셋 내 {len(mis_indices)}개의 Loc 오분류 샘플 중 첫 번째 샘플 선택")

plt.figure(figsize=(12, 3.5))

# 4개 각도(0°, 90°, 180°, 270°)에 대해 반시계 방향 90도 단위 회전 적용
for i, angle in enumerate([0, 90, 180, 270]):
    # np.rot90: 2차원 평면에서 k회 반시계 방향 90도 회전
    rotated_img = np.rot90(sample_img, k=i)
    
    # 모델 추론을 위해 배치 차원 추가: (64, 64, 3) -> (1, 64, 64, 3)
    probs = model.predict(rotated_img[None, ...], verbose=0)[0]
    pred_cls = class_names[np.argmax(probs)]
    conf = np.max(probs) * 100
    print(f"[{angle:3d}° 회전] 모델 예측: {pred_cls:9s} (신뢰도: {conf:.1f}%)")

    # 각 회전 이미지와 예측 결과 시각화
    plt.subplot(1, 4, i + 1)
    plt.imshow(rotated_img.astype("uint8"))
    plt.title(f"{angle}° -> {pred_cls}
({conf:.1f}%)", fontsize=10)
    plt.axis("off")

plt.suptitle("CNN의 회전 불변성(Rotation Invariance) 부재 검증 실험", fontsize=12)
plt.tight_layout()
plt.show()
```

## 1.5. 오분류 원인 및 회전 불변성(Rotation Invariance) 한계 분석

* **전체 테스트 정확도**: **73.33%** (150장 중 110장 정답, Macro 평균 Precision 0.78, Recall 0.73, F1-score 0.71)

![4강 CNN 혼동행렬]({{ '/images/images_반도체장비AI비전실무/cm_04.png' | relative_url }})
*그림 1-2. 4강 CNN 모델의 테스트 데이터(150장) 혼동행렬*

* **클래스별 분류 결과 및 오분류 분석**:
  * `Center`(Recall 0.93)와 `Edge-Ring`(Recall 0.97)은 비교적 뚜렷한 원형·고리 형태를 가지고 있어 대부분 정확하게 분류했습니다.
  * 반면 **`Loc` 유형은 Recall이 0.23(30장 중 7장만 정답)으로 가장 낮았습니다.** 혼동행렬을 보면 실제 `Loc` 30장 가운데 절반인 **15장을 `Scratch`로 잘못 분류**했고, 6장을 `Edge-Loc`으로, 2장을 `Center`로 예측했습니다. 또한 실제 `Scratch` 30장 중 7장은 `Edge-Loc`으로 오분류되었습니다.
  * `Loc`은 특정 구역에 불량이 뭉쳐 있는 형태이고 `Scratch`는 선 형태로 이어진 패턴이지만, 64x64 이미지로 축소된 상태에서는 길쭉하게 뭉친 `Loc`과 짧은 `Scratch`의 모양이 비슷해 보여 모델이 두 클래스를 많이 혼동한 것으로 생각됩니다.
* **오분류 샘플 4방향 회전(0°·90°·180°·270°) 실험 결과**:
  * `Scratch`로 잘못 분류된 실제 `Loc` 이미지 1장을 `np.rot90`으로 90°씩 반시계 방향 회전시켜 예측 확률 변화를 확인한 결과는 아래 표와 같습니다.

| 회전 각도 (`np.rot90` 단계) | 실제 클래스 | 모델 예측 결과 | 예측 확신도 | 판정 |
| :---: | :---: | :---: | :---: | :---: |
| **0°** (원본, `k=0`) | Loc | **Scratch** | **82.6%** | 오분류 |
| **90°** 회전 (`k=1`) | Loc | **Scratch** | **88.2%** | 오분류 |
| **180°** 회전 (`k=2`) | Loc | **Scratch** | **74.5%** | 오분류 |
| **270°** 회전 (`k=3`) | Loc | **Loc** | **91.7%** | **정답** |

  * **실험 해석**: 동일한 웨이퍼 불량 이미지임에도 **0°(82.6%), 90°(88.2%), 180°(74.5%)에서는 모두 `Scratch`로 잘못 예측하다가 270°로 회전시켰을 때만 `Loc`(91.7%)으로 올바르게 분류**했습니다.
  * 이는 기본 CNN이 이미지가 회전하더라도 무조건 같은 클래스로 인식하는 것(**회전 불변성, Rotation Invariance**)이 아니라, 학습 데이터에 많이 등장했던 특정 위치와 방향에 매우 민감하게 반응한다는 점을 보여줍니다. (참고: 0°·90°·180°·270° 회전 테스트는 **4강 오분류 실험**의 내용이며, 이어지는 5강 증강 실습에서는 `factor=0.25`(±90°) 및 지정 각도 `[0°, 15°, 45°, 90°]` 조건으로 회전 증강 효과를 검증합니다.)

# Part 2. 데이터 증강 실험 (05강 Mission 01~04)

## 2.1. 데이터 증강을 적용한 이유와 설정 방법 (최근접 이웃 보간법의 의미)
4강 실험에서 학습 이미지가 특정 방향이나 위치에 치우쳐 있으면 회전된 이미지를 다른 클래스로 예측할 수 있다는 점을 확인했습니다. 이에 따라 5강에서는 학습 이미지에 무작위 회전을 적용하는 **데이터 증강(Data Augmentation)**을 추가하여 다양한 방향의 패턴을 학습시키면 성능이 개선될 것이라는 가설을 세우고 실험을 진행했습니다.

Keras의 `layers.RandomRotation` 레이어를 사용하며 각 파라미터는 다음과 같이 설정했습니다.
* `factor=0.25`: 전체 360°를 기준으로 ±90°(360° × 0.25) 범위 안에서 무작위로 회전시킵니다. (만약 `factor=0.125`로 바꾸면 회전 범위는 절반인 ±45°가 됩니다.)
* `fill_mode="constant"`, `fill_value=0.0`: 이미지를 회전할 때 모서리에 새로 생기는 빈 공간을 일정한 값(`0.0`, 검은색 배경)으로 채워 기존 웨이퍼맵의 검은색 배경과 통일시킵니다.
* `interpolation="nearest"` (최근접 이웃 보간법):
  * 이미지를 회전시키면 픽셀 위치가 격자 사이로 이동하면서 새로운 픽셀값을 계산해야 합니다.
  * 일반적인 사진에서 자주 쓰는 `bilinear`(쌍선형 보간법)는 주변 픽셀값을 섞어 평균을 내기 때문에 경계 부분에 `0.8`, `1.4` 같은 중간 밝기 값(소수점)이 새로 만들어집니다.
  * 하지만 웨이퍼맵에서 각 픽셀은 단순한 밝기가 아니라 **배경(0), 정상 다이(1), 불량 다이(2)라는 구분된 의미를 가진 값**입니다. 따라서 주변 값을 섞지 않고 가장 가까운 픽셀값을 그대로 가져오는 `nearest`(최근접 이웃 보간법)를 사용해야 중간값이 생기지 않고 원래 데이터의 의미가 유지됩니다.

## 2.2. [실습 코드] 회전 증강 레이어 생성 및 6회 무작위 회전 시각화 (Mission 01~02)

```python
# 웨이퍼맵의 물리적 회전 대칭성을 학습시키기 위한 RandomRotation 파이프라인 구성
data_augmentation = keras.Sequential([
    layers.RandomRotation(
        factor=0.25,             # 회전 범위: [-0.25 * 2π, +0.25 * 2π] = [-90°, +90°] 사이 무작위 회전

        fill_value=0.0,          # 웨이퍼 외부 배경값인 검은색(0.0)으로 패딩
        interpolation="nearest"  # ★핵심★ 최근접 이웃 보간법: 픽셀 카테고리값(0, 127, 255)을 왜곡 없이 그대로 보존
    )
])

print("RandomRotation 증강 레이어 생성 완료 (보간법: nearest, 각도: ±90°)")
```

## 3.2. [실습 코드] 전체 불량률(`defect_ratio`) 추출 및 분포 확인 (Mission 01 활동 B)

```python
# [6강 Mission 01 - 활동 B.1 & B.2] 1차 특성: 전체 불량률(defect_ratio) 계산 함수 구현 및 적용
def defect_ratio(wafer_map):
    """
    웨이퍼 내 실제 유효 칩(0이 아닌 칩) 중 결함 칩(값이 2인 칩)이 차지하는 비율을 계산하는 함수
    
    수식: defect_ratio = (불량 칩 개수) / (유효 칩 전체 개수)
    - 웨이퍼 크기(26x26, 52x52 등)가 달라져도 0~1 사이로 정규화된 밀도를 추출
    """
    wafer_map = np.asarray(wafer_map)

    # 0(외곽 비유효 영역)을 제외한 실제 유효 칩 개수 계산
    valid_count = np.sum(wafer_map != 0)
    # 값이 2인 결함 칩 개수 계산
    defect_count = np.sum(wafer_map == 2)

    # 예외 처리: 유효 칩이 없는 비정상 데이터의 경우 0.0 반환 (ZeroDivisionError 방지)
    if valid_count == 0:
        return 0.0

    return defect_count / valid_count

# DataFrame 내 모든 웨이퍼맵(25,519장)에 대해 defect_ratio 함수를 일괄 적용
df['defect_ratio'] = df['waferMap'].apply(defect_ratio)
```

## 3.3. [실습 코드] 가장자리 불량률(`edge_ratio`) 추출 및 산점도 비교 (Mission 01 활동 C~D)

```python
# [6강 Mission 01 - 활동 C.2] 2차 특성: 가장자리 불량률(edge_defect_ratio) 계산 함수 구현
def edge_defect_ratio(wafer_map):
    """
    웨이퍼 중심으로부터의 거리를 계산하여 외곽 20% 가장자리 링 영역 내의 불량률을 산출하는 함수
    
    [도메인 배경]
    반도체 공정(CMP 평탄화, 에지 식각 가스 와류 등)의 특성상 가장자리에 불량이 집중되는
    Edge-Ring 및 Edge-Loc 패턴을 분별하기 위해 고안된 핵심 공간 특성입니다.
    """
    wafer_map = np.asarray(wafer_map)

    # 유효 칩 마스크(0이 아님)와 불량 칩 마스크(값이 2) 생성
    valid = wafer_map != 0
    defect = wafer_map == 2

    # 유효 칩이 하나도 없으면 0.0 반환
    if not np.any(valid):
        return 0.0

    # 2차원 좌표 인덱스 그리드 생성 (y: 행 좌표, x: 열 좌표)
    y, x = np.indices(wafer_map.shape)

    # 실제 유효 칩들의 평균 좌표를 계산하여 웨이퍼의 물리적 중심점(cy, cx) 산출
    cy = y[valid].mean()
    cx = x[valid].mean()

    # 중심점에서 각 칩 위치까지의 유클리드 거리 행렬 계산: d = sqrt((y-cy)^2 + (x-cx)^2)
    distance = np.sqrt((y - cy)**2 + (x - cx)**2)

    # 유효 칩 중 중심으로부터의 최대 거리(웨이퍼 반지름 R_max) 계산
    max_distance = distance[valid].max()

    # [가장자리 영역 정의] 유효 칩이면서 중심 거리가 반지름의 80% 이상인 외곽 20% 환형(Ring) 영역 마스크
    edge = valid & (distance >= max_distance * 0.8)

    edge_count = np.sum(edge)
    if edge_count == 0:
        return 0.0

    # 가장자리 영역 내에 위치한 불량 칩 개수 계산
    edge_defect_count = np.sum(defect & edge)
    
    # 가장자리 불량률 = (가장자리 내 불량 칩 수) / (가장자리 내 유효 칩 수)
    return edge_defect_count / edge_count
```

```python
# stratify=y: 클래스 불균형이 심하므로 각 불량 유형의 비율이 훈련셋/테스트셋에 동일하게 유지되도록 계층적 분할
train_idx, test_idx = train_test_split(
    np.arange(len(df)),
    test_size=0.2,             # 80:20 분할
    random_state=RANDOM_STATE, # 분할 시드 고정
    stratify=y                 # 계층적 분할 적용
)

# 인덱스를 사용하여 훈련 및 테스트 데이터셋 추출
X_A_train, X_A_test = X_A.iloc[train_idx], X_A.iloc[test_idx]
y_train, y_test = y.iloc[train_idx], y.iloc[test_idx]

# [기준 모델 A 학습: Random Forest 분류기]
model_A = RandomForestClassifier(
    n_estimators=100,           # 100개의 결정 트리 앙상블
    random_state=RANDOM_STATE,  # 트리 생성 난수 시드 고정
    n_jobs=-1                   # 가능한 모든 CPU 코어 병렬 활용
)
model_A.fit(X_A_train, y_train)

# 테스트 데이터 예측 및 성능 평가 지표 계산
pred_A = model_A.predict(X_A_test)
acc_A = accuracy_score(y_test, pred_A)
f1_A = f1_score(y_test, pred_A, average='macro') # 클래스별 불균형을 고려한 매크로 F1 점수

print(f"기준 모델 A 정확도 (Accuracy): {acc_A:.4f}")   # 약 0.5895
print(f"기준 모델 A Macro F1 점수:    {f1_A:.4f}")   # 약 0.5159
```

* **왜 가장 단순한 기준 모델 A(`defect_ratio` 1개)를 두고 모델 B(`+ edge_ratio`)와 비교할까?**
  * 새로운 특성을 추가했을 때 실제로 효과가 있는지 판단하려면 먼저 비교 기준이 되는 가장 단순한 **기준 모델(Baseline Model, A)**이 필요합니다. 가장 단순한 모델 A와 비교했을 때 특성을 추가한 모델 B의 성능이 더 낮거나 비슷하다면, 굳이 추가 계산 비용을 들여 복잡한 모델 B를 사용할 이유가 없기 때문입니다.
* **[참고: 모델 입력 전 처리(정규화) 안내]**
  * `defect_ratio`, `edge_ratio` 등은 이미 `0 ~ 1` 사이의 비율 값으로 계산되어 있고, 결정트리 기반인 `RandomForestClassifier`는 각 특성의 크기(스케일)에 민감하지 않아 별도의 `StandardScaler` 없이 그대로 입력합니다. (만약 추후 로지스틱 회귀·SVM·KNN 같은 거리/선형 기반 모델에 적용한다면 `StandardScaler` 정규화를 먼저 거치며, 모델 평가 단계에서는 클래스별 샘플 수 차이를 보정하기 위해 혼동행렬을 `normalize='true'`로 정규화합니다.)

* **[필수 기록 - 미션02 Q5] `random_state`, `stratify`, 그리고 행 인덱스를 저장한 이유**:
  * `random_state=42`: 데이터를 섞거나 결정트리를 만들 때 사용되는 난수 시드를 고정하여, 실험을 다시 실행해도 동일한 분할과 학습 결과가 재현되도록 합니다.
  * `stratify=y`: 클래스별 샘플 수 차이가 큰 데이터에서 학습 데이터(80%)와 테스트 데이터(20%)에 각 불량 유형의 비율이 원본과 동일하게 나뉘도록 유지해 줍니다.
  * **행 인덱스(`train_idx`, `test_idx`)를 저장한 이유**: 이후 `edge_ratio`를 추가한 모델 B나 개인 특성을 추가한 모델 C를 실험할 때, 새로 분할하지 않고 저장해 둔 인덱스를 그대로 사용하면 **모든 모델이 완전히 동일한 웨이퍼 샘플들로 학습하고 동일한 테스트 샘플로 평가**받게 되어, 성능 차이가 오직 '추가된 특성' 때문인지 공정하게 비교할 수 있습니다.

```python
sns.barplot(data=results_plot, x='Model', y='Score', hue='Metric', palette='muted')
```

| **특성 이름** | `mid_defect_ratio` (중간 영역 불량률) |
| **특성이 나타내는 정보** | 웨이퍼 중심에서 최대 거리의 **30% 이상 ~ 70% 이하**인 중간 고리(환형) 영역 내 유효 칩 중 불량 칩의 비율 |
| **대상 불량 유형** | `Center`, `Donut`, `Loc` 등 웨이퍼 내부 및 중간 영역에 분포하는 불량 유형 |
| **선택한 이유** | 기존 모델 B는 전체 불량률과 외곽(80% 이상) 불량률만 가지고 있어 웨이퍼 내부의 위치 차이를 알 수 없으므로, 중심부(30% 미만)와 외곽(70% 초과) 사이의 중간 영역 불량률을 추가하여 내부 불량들의 위치 차이를 표현하고자 함 |
| **계산 방법** | 배열 중심`(h/2, w/2)`에서 각 픽셀까지의 거리를 구한 뒤, 최대 거리의 `0.3 ~ 0.7` 범위에 속하는 유효 칩(`wafer != 0`) 개수 대비 해당 영역의 불량 칩(`wafer == 2`) 개수의 비율을 계산 |

> **설계 가설**: *"중간 영역 불량률(`mid_defect_ratio`) 특성을 추가하면 웨이퍼 안쪽에서 서로 혼동되던 `Center`, `Donut`, `Loc` 불량 유형의 분류 성능(Recall)이 개선될 것이다."*

```python
# [7강 Mission 03 - 활동 B.3 & B.4] 나만의 도메인 특성 함수(mid_defect_ratio) 구현 및 수치 유효성 확인
def mid_defect_ratio(wafer_map):
    """
    웨이퍼 중심으로부터 30% ~ 70% 사이의 중간 환형(Donut Ring) 영역 내 불량률을 계산하는 함수
    
    [설계 가설]
    - Donut 불량: 웨이퍼 중간 환형 영역(30%~70%)에 집중적으로 도넛 모양의 결함 형성
    - Center 불량: 중심부(0%~30%)에 결함 집중 -> 중간 영역 결함률 낮음
    - Edge 불량: 외곽(80%~100%)에 결함 집중 -> 중간 영역 결함률 낮음
    따라서 'mid_defect_ratio'는 Donut 불량을 다른 패턴과 극명하게 분리할 수 있는 핵심 특성이 됨!
    """
    wafer_map = np.asarray(wafer_map)
    h, w = wafer_map.shape
    center_y, center_x = h / 2, w / 2

    # 고속 브로드캐스팅 연산을 위한 오픈 그리드 생성
    y, x = np.ogrid[:h, :w]
    # 중심 좌표로부터 각 픽셀까지의 거리 행렬 계산
    dist = np.sqrt((y - center_y)**2 + (x - center_x)**2)
    max_dist = np.max(dist)

    # [중간 영역 마스크 정의] 중심 거리 30% 이상 ~ 70% 이하 구간 선택
    mid_mask = (dist >= max_dist * 0.3) & (dist <= max_dist * 0.7)

    # 중간 영역 내 유효 칩(0이 아님) 및 불량 칩(값이 2) 개수 산출
    mid_valid = np.sum((wafer_map != 0) & mid_mask)
    mid_defect = np.sum((wafer_map == 2) & mid_mask)

    # 0으로 나누기 방지 및 중간 영역 불량률 반환
    return mid_defect / mid_valid if mid_valid > 0 else 0.0

# [함수를 전체 데이터에 적용하여 'my_feature' 열 생성]
my_feature_function = mid_defect_ratio
my_feature_values = original_df['waferMap'].apply(my_feature_function)
feature_df['my_feature'] = my_feature_values.to_numpy()

# [수치적 유효성 검증: NaN, Inf, 이상치 존재 여부 확인]
print(f"개인 특성 최솟값: {feature_df['my_feature'].min():.4f}")
print(f"개인 특성 최댓값: {feature_df['my_feature'].max():.4f}")
print("특성 기술 통계량:")
display(feature_df['my_feature'].describe())

is_finite = np.isfinite(feature_df['my_feature'].to_numpy()).all()
```

  2. **단일 특성 분포에서는 겹쳐 보였는데 모델 성능은 크게 향상된 이유**: 앞선 박스플롯(그림 4-1)에서 `mid_defect_ratio` 하나만 단독으로 보았을 때는 `Center`와 `Loc`, `Edge-Loc`의 값 범위가 비슷해 보였습니다. 하지만 RandomForest 모델은 이 특성을 단독으로 쓰지 않고 **기존의 `defect_ratio`(전체 불량률), `edge_ratio`(외곽 불량률)와 함께 조합하여 판단**합니다. 예를 들어 전체 불량률(`defect_ratio`)은 어느 정도 높은데 외곽 불량률(`edge_ratio`)과 중간 영역 불량률(`mid_defect_ratio`)이 상대적으로 낮다면, 남은 불량 칩들은 자연히 **중심부(중심 거리 30% 미만 구간)에 집중되어 있다(`Center`)**고 추론할 수 있습니다. 실제로 혼동행렬(그림 4-3)에서도 모델 B에서 `Center`가 `Loc`으로 잘못 분류되던 비율이 0.20에서 0.11로 줄어들고, `Donut`이 `Center`로 오분류되던 비율도 0.32에서 0.19로 크게 줄어든 것을 확인할 수 있습니다.
  3. **남겨진 한계(`Scratch`)**: 반면 `Scratch`는 모델 C에서도 Recall이 0.2185(42%가 `Loc`으로 오분류)로 거의 개선되지 않았습니다. 이는 내가 설계한 `mid_defect_ratio` 역시 원형 고리 면적 안의 불량 비율만 계산할 뿐, 불량 칩들이 좁고 긴 선 모양으로 이어져 있는 형태적 특징은 담지 못하기 때문이라고 생각됩니다.

## 5.2. '평가 → 전처리' 반복 과정과 실험 조건 통제의 중요성

![머신러닝 프로세스와 반복 루프]({{ '/images/images_반도체장비AI비전실무/ml_process.jpg' | relative_url }})
*그림 5-2. 머신러닝 프로세스 다이어그램과 '성능 개선이 필요한 경우 반복(평가 → 전처리)' 과정*

이번 4강부터 7강까지의 실습을 이어서 진행하면서 가장 크게 배운 점은 위 그림 5-2의 머신러닝 프로세스에서 **`[STEP 05 평가]`에서 `[STEP 03 전처리]`로 돌아가는 "성능 개선이 필요한 경우 반복" 화살표의 의미**였습니다.
* 처음에는 데이터를 넣고 모델을 한 번 학습시키면 끝나는 줄 알았지만, 실제로는 **모델을 평가하고 혼동행렬을 통해 '어떤 불량 유형을 왜 틀렸는지' 확인한 뒤, 다시 전처리 단계로 돌아가 새로운 방법을 시도하는 과정의 연속**이었습니다.
  * 4강 평가에서 `Loc` 오분류와 회전 문제를 발견해 5강의 이미지 증강 전처리를 시도했고,
  * 5강 평가에서 무작위 회전이 오히려 성능을 낮춘다는 것을 확인하고 6강에서 숫자 특성을 추출하는 특성공학 전처리로 방향을 바꾸었으며,
  * 6강 모델 B의 혼동행렬 평가에서 내부 불량(`Center`, `Donut`, `Loc`)이 겹치는 한계를 발견하고 다시 전처리 단계로 돌아가 7강의 `mid_defect_ratio` 특성을 직접 만들어 추가함으로써 성능을 58.95%(모델 A) → 68.53%(모델 B) → 75.24%(모델 C)로 단계적으로 높일 수 있었습니다.
* 또한 이 과정에서 **실험 조건을 동일하게 통제하는 것(`random_state` 고정, `stratify` 적용, 동일한 `train_idx`·`test_idx` 행 인덱스 사용, 동일한 모델 하이퍼파라미터 유지)**이 왜 중요한지도 분명히 알게 되었습니다. 만약 특성을 바꿀 때마다 학습 데이터나 모델 설정이 함께 바뀌었다면, 성능이 올랐을 때 그것이 내가 만든 `mid_defect_ratio` 덕분인지 아니면 데이터가 우연히 쉽게 나뉘었기 때문인지 알 수 없었을 것입니다.

## 5.3. 수업과 실습을 통해 생각해 본 현장 활용 관점 (입문자 관점)
이번 수업을 듣기 전에는 AI 분류 모델이 웨이퍼맵을 보고 `Edge-Ring`이나 `Scratch`라고 판정하면, 그것만으로 곧바로 "식각 장비가 고장 났다"거나 "이송 로봇에 문제가 생겼다"고 원인을 확정 지을 수 있는 줄 알았습니다.
하지만 5강 도메인 지식 자료와 실습을 공부하면서, **같은 불량 패턴이라도 여러 공정 조건에서 발생할 수 있기 때문에 웨이퍼맵 분류 모델만으로 특정 장비의 고장을 단정 지을 수는 없다**는 점을 처음 알게 되었습니다. 대신 수많은 웨이퍼가 쏟아지는 현장에서 사람이 일일이 눈으로 확인하기 전에, 모델이 불량 패턴을 빠르게 먼저 분류해 주면 **"어느 공정이나 장비를 우선적으로 점검해 볼지 조사 범위를 좁혀주는 보조 역할"**로서 큰 도움이 될 것 같다고 생각했습니다.

또한 입문자 입장에서 흥미로웠던 점은, 무조건 복잡하고 무거운 딥러닝(CNN)만 쓰이는 것이 아니라 우리가 직접 만든 **3개의 단순한 비율 숫자(`defect_ratio`, `edge_ratio`, `mid_defect_ratio`)만으로도 `Edge-Ring`(93.3%)이나 `Center`(84.4%)처럼 자주 발생하는 패턴을 꽤 정확하고 빠르게 찾아낼 수 있다**는 것이었습니다. 특히 현장에서 `Loc`을 `Scratch`로 잘못 분류하면 엉뚱한 장비를 먼저 조사하느라 시간을 허비할 수 있다는 설명을 들으면서, 왜 전체 정확도 숫자 하나만 보지 않고 혼동행렬과 클래스별 정밀도(Precision)·재현율(Recall)을 꼼꼼히 따져봐야 하는지 이해할 수 있었습니다.

## 5.4. 아쉬웠던 점과 앞으로 더 시도해 보고 싶은 개선 방향
이번 개인 실험에서 `mid_defect_ratio`를 추가해 `Center`의 Recall을 84.40%까지 높인 점은 뿌듯했지만, **`Scratch` 유형의 Recall이 21.85%에 머물러 끝까지 잘 분류하지 못한 점**이 가장 아쉬웠습니다.
원인을 생각해 보니, 내가 사용한 3가지 특성은 모두 웨이퍼 전체, 가장자리, 중간 고리처럼 **'특정 면적 안에 불량 칩이 몇 퍼센트나 있는가'만 계산하는 방식**이었습니다. 그래서 불량 칩들이 둥글게 모여 있는 패턴은 잘 찾았지만, `Scratch`처럼 불량 칩 개수는 적으면서 가늘고 길게 줄지어 나타나는 모양은 면적 비율만으로는 `Loc`과 구별할 수 없었던 것 같습니다.

앞으로 파이썬과 데이터 전처리를 조금 더 연습해서 이 모델을 개선해 본다면, 아직 어려운 알고리즘은 잘 모르더라도 수업 워크북의 특성 아이디어 예시에서 보았던 방법들부터 차근차근 직접 구현해 보고 싶습니다.
1. **상하/좌우 불량률 차이 추가**: 예제 코드로 보았던 `top_bottom_difference()`처럼 웨이퍼를 위·아래나 왼쪽·오른쪽으로 나누어 불량이 한쪽으로 치우친 정도를 계산하면, 한쪽 구석에 몰리는 `Edge-Loc`이나 `Loc`을 더 잘 구분할 수 있을 것 같습니다.
2. **불량 칩들의 위치 퍼짐 정도(분산)나 연결된 크기 계산**: 불량 칩(`wafer == 2`)들의 좌표가 한 점 근처에 좁게 뭉쳐 있는지(`Loc`), 아니면 길게 뻗어 있는지(`Scratch`), 혹은 서로 이웃해서 연결된 불량 칩들이 얼마나 이어져 있는지를 숫자로 계산하는 특성을 하나 더 만들어 추가해 보고 싶습니다.
3. **CNN과 숫자 특성의 비교 연습**: 4~5강에서 다루었던 CNN 모델도 데이터를 조금 더 모으거나 에포크 수, 레이어 구성을 조절해 보면서, 이미지 형태를 직접 보는 CNN이 `Scratch` 같은 선형 불량을 숫자 특성 모델보다 얼마나 더 잘 잡아낼 수 있는지 비교해 보고 싶습니다.
